# JavaScript 行程路径闭环死循环问题分析

## 1. 问题背景

旅游行程系统根据城市之间的出发、到达关系，以及时间顺序生成连续路径。

典型数据：

```
北京 → 东京
东京 → 大阪
大阪 → 北京
```

该数据形成闭环。

## 2. 问题现象

部分闭环数据处理时出现：

- 程序长时间运行
- CPU占用升高
- 页面无响应

## 3. 根本原因

路径查找逻辑不断寻找下一节点，但没有有效终止条件。

执行过程：

```
北京
 ↓
东京
 ↓
大阪
 ↓
北京
 ↓
东京
...
```

形成无限循环。

## 4. 优化方案

### 4.1 记录已访问城市

使用 Set 保存访问节点：

```javascript
const visitedCities = new Set()
```

发现重复节点时结束当前路径。

### 4.2 记录已使用行程段

避免同一条边重复使用：

```javascript
const usedTrips = new Set()
```

### 4.3 增加最大循环保护

异常数据情况下增加兜底：

```javascript
if (count > trips.length) {
  break
}
```

## 5. 经验总结

图路径算法必须考虑：

- 自闭环
- 多出口节点
- 重复边
- 异常数据
- 无限搜索

不能假设业务数据永远正确。
